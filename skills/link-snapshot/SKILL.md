# 链接核验与快照

把用户提供的链接或报告交给本 Skill 的 [快照脚本](scripts/snapshot.js)。无需启动网页或 HTTP 服务，也不需要 API Key。

## 执行

- 用户只说“帮我核验”或“生成快照”时，先使用当前对话里明确要处理的链接或报告；没有可确定的输入再询问。不要重新搜索或猜测来源。
- 报告文本保存为临时 UTF-8 文件，用 `--input` 传入；现有 TXT、Markdown、HTML 文件可直接使用。输入含有超链接时保留真实 href，避免只保留显示文字。
- 在本 Skill 目录运行下列命令；输入和输出使用绝对路径。输出放在当前任务工作目录下或用户指定目录，不能放进 Skill 安装目录。

```sh
node scripts/snapshot.js --input "/绝对路径/报告.txt" --output "/绝对路径/快照"
```

少量链接可重复使用 `--url`。通过结构化参数传递或正确 shell 引用，不把报告内容拼进 shell 命令。

```sh
node scripts/snapshot.js --url "https://example.com" --output "/绝对路径/快照"
```

每批最多 100 个不同链接，默认 4 个并发。超过 100 个先用 `--parse-only` 提取，再拆成每批不超过 100 个继续处理。只有用户指定或实际资源情况需要调整时才使用 `--concurrency N`（1–16）；“每批 100 条”不代表 100 个并发。

脚本优先使用已安装的 Playwright，也会查找 Codex 自带运行库；自动使用本机 Chrome。若缺少依赖，在本 Skill 目录按 `package.json` 安装 Playwright；没有可用浏览器时安装 Chromium，或设置 `CHROMIUM_EXECUTABLE_PATH`。不要因此重建网页工具。

## 快照规则

- 博客、新闻等文章页按元数据和正文结构识别，需要时滚动加载后保存长图；普通首页、工具页、列表页截首屏。
- X / Twitter 使用公开的具体帖子链接，匿名访问。只截对应目标帖子一次，不能回退到其他帖子或整页截图。
- 文章滚动加载最多等待 15 秒，图片最高 40,000 像素、最宽 1920 像素。持续加载或超过上限会标注部分截取，不视作完整长图。
- 相同链接去重；同一 X 帖子的 twitter.com / x.com 别名和跟踪参数合并。本次调用重新访问来源，不从历史批次搬用截图。
- 使用真实浏览器执行结果。404、登录、验证码、限流、超时分别说明；无法访问不能直接归因为“AI 编造链接”。失败按单条记录，不影响其余链接。除用户要求或明确的暂时性错误外，不反复重试；暂时性错误最多重试一轮失败链接。

## 交付

脚本标准输出是简短 JSON 摘要和绝对文件路径，进度输出到 stderr；需要完整结果时读取 `reportPath` 对应文件，不必把 100 张图全部加载进对话。

- `snapshots.zip`：PNG 和 `manifest.json`，包含原始网址、最终网址、标题、截图时间、范围、尺寸和截断提示。
- `report.json`：逐条访问状态、失败原因及本地截图路径。
- `summary.txt`：便于阅读的逐条结果清单。

回答说明总链接数、快照数、失败数与部分截取数，提供 ZIP 和清单的可点击本地链接。少量链接可直接展示图片；批量任务选少量有代表性的截图查看，说明实际观察到的缺陷，避免无必要地逐张读取图片。

“核验”仅指访问状态和实际快照。不要输出主张支持度、引用匹配、作者比对、来源可信度分级或报告风险评分，也不要把截图说成事实真实性证明。
